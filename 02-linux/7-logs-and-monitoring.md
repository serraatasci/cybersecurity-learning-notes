# Logs and Monitoring

This page contains my notes on Linux logs, log monitoring, authentication events, firewall logs, and basic security monitoring.

---

## What Are Logs?

Logs are records created by the operating system, applications, and services.

They help track what happened on a system.

Logs can contain information such as:

- Login attempts
- System errors
- Service activity
- Network connections
- Application requests
- Security events

Logs are very important in both system administration and cybersecurity.

---

# `/var/log`

Many Linux log files are stored under:

`/var/log`

This directory contains logs generated by the system and installed services.

Example:

`ls /var/log`

The exact files depend on the Linux distribution and installed applications.

---

## Common Types of Logs

Examples may include:

- Authentication logs
- System logs
- Web server logs
- Firewall logs
- Application logs
- Package management logs

---

# Authentication Logs

Authentication logs contain information related to user authentication and login activity.

Depending on the Linux distribution, authentication events may be stored in files such as:

`/var/log/auth.log`

These logs can contain information about:

- Successful logins
- Failed login attempts
- SSH authentication
- `sudo` usage
- User authentication events

---

## Searching Authentication Logs

Because log files can become large, `grep` can be used to search them.

Example:

`grep "Failed password" /var/log/auth.log`

This can help identify failed login attempts.

Another example:

`grep "sshd" /var/log/auth.log`

This can help display SSH-related events.

---

# Apache Logs

Apache is a web server that can generate logs for web requests and errors.

Apache logs are commonly stored under:

`/var/log/apache2/`

Two important examples are:

`access.log`

and:

`error.log`

---

## `access.log`

The access log records requests made to the web server.

It can contain information such as:

- Client IP address
- Requested resource
- HTTP method
- Response status
- Request time

Example:

`cat /var/log/apache2/access.log`

Because access logs can contain many entries, searching is often more useful.

Example:

`grep "192.168.1.10" /var/log/apache2/access.log`

This searches for requests associated with a specific IP address.

---

## `error.log`

The error log records problems encountered by Apache.

Example:

`cat /var/log/apache2/error.log`

This can help identify:

- Configuration problems
- Missing files
- Application errors
- Server-side issues

---

# Firewall Logs

A firewall controls network traffic according to configured rules.

Linux systems may use tools such as UFW.

UFW stands for:

Uncomplicated Firewall

It provides a simpler interface for managing firewall rules.

---

## UFW Status

To check firewall status:

`sudo ufw status`

This can show whether the firewall is enabled and which rules are configured.

---

## UFW Logs

If logging is enabled, UFW-related events may appear in system log files.

These logs can help identify:

- Blocked connections
- Allowed connections
- Source IP addresses
- Destination ports

Firewall logs are useful when investigating unusual network activity.

---

# Fail2ban

Fail2ban is a security tool that monitors log files for suspicious activity.

It can detect repeated failed authentication attempts and temporarily block the source IP address.

A common example is repeated SSH login failures.

The basic idea is:

`Repeated Failed Logins → Detection → Temporary IP Block`

---

## Why Fail2ban Is Useful

Without protection, an attacker may repeatedly try passwords against a service.

Fail2ban can monitor the related log files and react when too many failures occur.

This can help reduce brute-force attempts.

---

# Log Rotation

Log files continuously grow as new events are recorded.

If logs were never managed, they could eventually consume a large amount of disk space.

Log rotation helps control this.

The process may:

- Rename old log files
- Create a new active log file
- Compress older logs
- Delete very old logs after a defined period

---

## Why Log Rotation Matters

Log rotation helps:

- Prevent logs from using excessive disk space
- Keep log files manageable
- Preserve historical records
- Organize logs by time period

---

# Reading Logs

Several Linux commands can be used to inspect logs.

## `cat`

Displays the entire file.

Example:

`cat /var/log/auth.log`

This is useful for small files.

---

## `less`

Allows easier navigation through a large file.

Example:

`less /var/log/auth.log`

To exit:

`q`

---

## `tail`

Displays the last lines of a file.

Example:

`tail /var/log/auth.log`

This is useful for seeing the most recent events.

---

## `tail -f`

Monitors a file as new lines are added.

Example:

`tail -f /var/log/auth.log`

This is useful for real-time monitoring.

To stop it:

`Ctrl + C`

---

## `grep`

Searches for specific information inside logs.

Example:

`grep "Failed" /var/log/auth.log`

This returns only lines containing the word `Failed`.

---

# Combining Log Commands

Linux commands can be combined using pipes.

Example:

`grep "Failed" /var/log/auth.log | wc -l`

This searches for failed authentication entries and counts how many matching lines exist.

Another example:

`cat access.log | grep "404"`

This searches the web server log for requests that returned HTTP status code `404`.

---

# Basic Security Monitoring Workflow

A simple log investigation can look like this:

1. Identify the relevant log file
2. Open or search the log
3. Look for unusual events
4. Filter by IP address, username, or error
5. Compare repeated events
6. Determine whether the activity looks normal or suspicious

For example:

`grep "Failed password" /var/log/auth.log`

can be used to identify failed login attempts.

Then:

`grep "Failed password" /var/log/auth.log | wc -l`

can count them.

---

# Why Logs Matter in Cybersecurity

Logs provide evidence of what happened on a system.

They can help identify:

- Failed authentication attempts
- Unauthorized access
- Suspicious IP addresses
- Web attacks
- Service failures
- Firewall activity
- Repeated login attempts

Because of this, log analysis is one of the foundations of security monitoring and incident investigation.

## Key Takeaway

Linux logs provide a history of system, user, application, and network activity.

A simple security monitoring mindset is:

`Collect Logs → Search → Filter → Identify Patterns → Investigate`

Understanding how to locate and analyze logs is an important foundation for cybersecurity.
